### 1.2 Circle → Group 涉及面

Claude 识别出需要改动的 9 类位置：

| 类别 | 旧 | 新 |
|------|---|---|
| 实体类 | `Circle` / `CircleTranslation` | `Group` / `GroupTranslation` |
| DB 表 | `t_community_circle` / `t_community_circle_translation` | `t_community_group` / `t_community_group_translation` |
| 字段 | `circle_id` / `circleId` | `group_id` / `groupId` |
| API 路径 | `/api/v1/circles`、`/api/v1/admin/circles` | `/api/v1/groups`、`/api/v1/admin/groups` |
| Permission Code | `circle:view:any`、`circle:manage:any` | `group:view:any`、`group:manage:any` |
| 错误码常量 | `CIRCLE_NOT_FOUND` 等 4 项 | `GROUP_NOT_FOUND` 等 |
| 任务编号 | `CIRCLE-01~06` | `GROUP-01~06` |
| 类名 | `Circle*Service`、`Circle*Controller` 等 | `Group*Service`、`Group*Controller` 等 |
| Redis Key | `circle:config:*`、`circle:permissions:*` | `group:config:*`、`group:permissions:*` |

**关键约束**：
- 中文术语「圈子」**保留不变**（用户可见展示），仅技术命名统一为 `group`
- Vant 的 `van-circle` 组件名属于第三方库 API，**不能改**

### 1.3 替换难点与解决方案

#### macOS BSD sed `\b` 不支持

初次使用 `sed -E 's|\bcircle\b|group|g'` 失败——BSD sed 不支持 `\b` 字边界。

**解决方案**：改用 Python 配合 `re.sub(r'\bCircle\b', 'Group', text)`，并在替换前将 `van-circle` 暂存为占位符以保护它。

```python
# 伪代码
text = text.replace('van-circle', '__VAN_CIRCLE_PLACEHOLDER__')
text = re.sub(r'\bCircle\b', 'Group', text)
text = re.sub(r'\bcircle\b', 'group', text)
text = text.replace('__VAN_CIRCLE_PLACEHOLDER__', 'van-circle')
```

#### 下划线边界遗漏

首次替换后发现以下残留（下划线不属于 `\b` 边界）：
- `circleName`（驼峰内部）
- `admin_circle`（下划线连接）
- `uk_circle_name`（索引名）
- `idx_question_circle_status_created`（索引名）

**解决方案**：补一轮显式 sed 模式针对这些下划线连接的情况。

## 关键经验

1. **macOS BSD sed 不支持 `\b` 字边界**——批量重命名时优先用 Python `re.sub` 配合占位符保护策略。

2. **下划线不属于 `\b` 边界**——驼峰内部、下划线连接的 case 需补一轮显式模式（`circleName`、`admin_circle`、`uk_circle_name`）。

3. **文档分层是渐进识别的过程**——v1.0.0 时所有内容混在 `产品架构.md`；v1.3.0 才意识到需要把"项目级 / 需求级 / 模块级"分层，并新建中间层 `prd/技术方案.md`。

4. **重命名是高频活动，每次都要扫一遍交叉引用**——本日 4 次重命名（Circle、CMS、后端服务、国际化文本），合计 100+ 处引用更新；先 grep 全项目再批量 sed/Edit 是最稳的工作流。

5. **CHANGELOG 历史条目要保留原貌**——新的重命名只更新当前活跃引用，CHANGELOG 中早期版本的"原文件名保留"等表述属于历史快照，不能改。

6. **写 PRD 时极易引入"技术语言"漂移**——产品架构 §3 sequence 图原本写 `community-service`、`UOP 审核平台` 等技术名词，对纯产品读者不友好；要持续抓 review，把"前端 / 后端服务 / 审核平台 / 推送服务"这种产品级抽象名补上。

7. **小修复也可能藏着事实错误**——如 6.5.2 提到的"采纳机制"误述为单采纳——一次重写引入了一个与 BR-5.4-03 矛盾的事实错误，要靠交叉对照 PRD/00-总览/OQ 才能发现。
