# Prompt: 数据库 Schema 生成

> **适用角色**：后端 / DBA
> **输出工件**：MySQL DDL + MyBatis Plus Entity + Mapper XML

---

## 你需要先读这些文档

1. `tasks/任务清单.md` 中对应任务行（如 `GROUP-01`、`QLIST-01`；若按模块直接开发可跳过）
2. `requirement/00-需求总览.md` 第 1.4 节（命名规范）
3. `requirement/modules/<目标模块>.md` 第 5.x.6 节（数据对象 + ER 图）
4. `design/数据模型.md`
5. `standard/技术架构.md` 第 4.4 节（数据库规范）、第 6 章（数据存储）

## 你需要输出

### 1. DDL `migrations/V<n>__create_<table>.sql`

要求：
- 表名 `t_community_<entity>`，如 `t_community_question`
- 字段使用 snake_case，与 PRD 5.x.6 一致
- 必须字段：`id BIGINT AUTO_INCREMENT PRIMARY KEY`、`created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP`、`updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP`、`deleted TINYINT DEFAULT 0`
- 字段注释：用 `COMMENT 'xxx'`，与 PRD 字段说明一致
- 索引：
  - 外键字段必须建索引：`KEY idx_xxx_yyy(yyy)`
  - 复合索引遵循最左前缀：`KEY idx_question_group_status_created(group_id, review_status, created_at DESC)`
  - 唯一索引：`UNIQUE KEY uk_xxx_yyy(yyy)`
- 字符集：`utf8mb4 / utf8mb4_unicode_ci`
- 引擎：`InnoDB`

### 2. Entity `entity/<Module>.java`

要求：
- `@TableName("t_community_xxx")` MyBatis Plus 注解
- 字段类型与 DDL 对应：BIGINT → Long, VARCHAR → String, JSON → String/Object（用 TypeHandler）
- `@TableField` 标注非默认映射的字段
- `@TableLogic` 标注 `deleted` 字段实现软删除
- Lombok `@Data` 简化 getter/setter

### 3. Mapper `mapper/<Module>Mapper.java` + XML

要求：
- 简单查询用 `BaseMapper<T>` 内置方法
- 复杂查询写 XML，避免在注解中拼 SQL
- 涉及 JOIN 的查询用 `<resultMap>` 显式映射

### 4. 数据迁移脚本（如涉及历史数据）

要求：
- 增量迁移：`V<n>__add_xxx.sql`
- 数据回填：分批 `LIMIT 1000` 避免锁表
- 回滚脚本：`V<n>__rollback_xxx.sql`

## 严格约束

| 项 | 规则 |
|---|------|
| **追溯注释** | DDL 文件顶部用注释标注引用的 PRD 章节（如 `-- 来源: requirement/modules/05.02-圈子首页.md §5.2.6`） |
| **类型选择** | 主键 BIGINT；状态/布尔 TINYINT；金额 DECIMAL(10,2)；时间 TIMESTAMP；枚举 VARCHAR(20) 不用 ENUM 类型 |
| **字段长度** | 标题 VARCHAR(200)；描述 TEXT；昵称 VARCHAR(50)；URL VARCHAR(500) |
| **数组/对象** | 用 JSON 类型，配合 MyBatis JsonTypeHandler |
| **VARCHAR 字符长度** | 中文 1 字符 = 1 length，不需要 ×3 |
| **必须字段** | id / created_at / updated_at / deleted（每张表） |
| **冗余计数** | 如 `answer_count`，由 trigger 或事件维护，禁止 SELECT COUNT(*) 实时计算 |
| **分表预留** | 大表（question/answer/notification）字段中保留 `shard_key`，便于后续 ShardingSphere |

## 自检清单（输出末尾必填）

- [ ] 表名遵循 `t_community_xxx` 命名
- [ ] 字段与 PRD 5.x.6 完全对应
- [ ] 必须字段（id / created_at / updated_at / deleted）齐全
- [ ] 索引覆盖：外键、列表筛选字段、唯一约束
- [ ] 字符集 utf8mb4
- [ ] 注释完整，与 PRD 字段说明一致
- [ ] 是否预留分表 shard_key（大表）
- [ ] DDL 可逆（提供 rollback 脚本）

## 反例

```sql
-- ❌ 没有时间戳和软删除
CREATE TABLE question (
    id INT,
    title VARCHAR(200)
);

-- ❌ 用 ENUM 类型（升级困难）
review_status ENUM('PENDING', 'APPROVED')

-- ❌ 字符集不对
CREATE TABLE xxx (...) CHARSET=utf8;

-- ✅
CREATE TABLE t_community_question (
    id BIGINT NOT NULL AUTO_INCREMENT PRIMARY KEY COMMENT '问题 ID',
    title VARCHAR(200) NOT NULL COMMENT '标题',
    review_status VARCHAR(20) NOT NULL DEFAULT 'PENDING' COMMENT '审核状态: PENDING/APPROVED/REJECTED',
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    deleted TINYINT NOT NULL DEFAULT 0,
    KEY idx_question_group_status_created (group_id, review_status, created_at DESC),
    KEY idx_question_author (author_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='问题主表';
```
