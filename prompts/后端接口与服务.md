# Prompt: 后端接口与服务生成

> **适用角色**：Java 后端
> **输出工件**：Spring Boot Controller（接口层）/ Service（业务层）/ DTO / VO / Mapper

---

## 你需要先读这些文档

1. `tasks/任务清单.md` 中对应任务行（如 `QPOST-02`、`QDETAIL-01`；若按模块直接开发可跳过）
2. `requirement/00-需求总览.md` 第 1.4 节（术语）、第 1.5 节（角色权限）、第 6 节（全局规则）
3. `design/数据模型.md`（字段类型 ER）+ `design/权限设计.md`（Permission Code）
4. `requirement/modules/<目标模块>.md` 全文（重点 5.x.4 BR、5.x.5 EX、5.x.6 数据对象、5.x.7 状态机、5.x.10 API）
5. `standard/技术架构.md` 第 4 章（后端规范）、第 5 章（接口）、第 6 章（数据存储）、第 7 章（消息事件）、第 10 章（安全）

## 你需要输出

### 1. Controller `controller/<Module>Controller.java`

要求：
- `@RestController` + `@RequestMapping("/api/v1/...")` + `@Validated`
- 路径与 PRD 5.x.10 完全一致
- 鉴权：`@SaCheckPermission("xxx:yyy:zzz")`，code 必须在 `design/权限设计.md`中定义
- 入参用 `@RequestBody @Valid <Module>CreateDTO`
- 出参用 `Result<...>` 包裹

### 2. Service `service/<Module>Service.java` + impl

要求：
- 业务逻辑编排在此层；Controller 不能写业务
- 事务：`@Transactional` 标注；外部调用（UOP、FCM）放事务外
- 状态机：用枚举 + Service 方法守门，禁止 Controller 直接 setStatus
- 事件发布：状态转换/审核结果用 `applicationEventPublisher.publishEvent`，由 listener 异步处理通知 / MQ
- 缓存：列表/详情读 Redis，写后删（Cache-Aside），key 遵循 `standard/技术架构.md` 6.2

### 3. DTO/VO `dto/request/`、`dto/response/`、`vo/`

要求：
- `*CreateDTO`：含 JSR-303 注解（`@NotBlank`、`@Size(min=5, max=200)`、`@Valid`）
- `*VO`：返回前端，剔除敏感字段（`author_id` 转 `authorId`、`phone` 脱敏）
- 转换用 MapStruct，禁手写 setter

### 4. 异常处理

要求：
- 业务异常抛 `BusinessException(ErrorCode.XXX)`
- 错误码使用 `design/错误码.md`，禁止自定义新码
- 全局 `@RestControllerAdvice` 统一捕获

### 5. 消息事件（如涉及）

要求：
- 异步通知 / 推送 / 搜索索引 → RabbitMQ
- Exchange/Queue/Routing Key 遵循 `standard/技术架构.md` 7.1 表

## 严格约束

| 项 | 规则 |
|---|------|
| **追溯注释** | 每个生成文件顶部用注释标注引用的 BR/AC 编号（如 `// BR-5.3-01, AC-5.3-05`），便于反向追溯 |
| **错误码** | 使用 `design/错误码.md` 中的常量名（如 `ErrorCode.CONTENT_SENSITIVE`），禁止魔法数字 |
| **Permission Code** | 使用 `design/权限设计.md` 中的常量，禁止裸字符串 |
| **命名** | 类 PascalCase，字段 snake_case (DB) / camelCase (Java)，枚举 UPPER_SNAKE_CASE |
| **分层** | Controller → Service → Mapper；禁止 Controller 直接调 Mapper |
| **校验** | 入参 JSR-303；业务校验在 Service 用 `Assert.xxx` |
| **审计** | 写操作必须记录 `AuditLog`（管理员后台操作） |
| **国际化** | 错误消息使用 i18n key，由 `MessageSource` 解析 |
| **幂等** | 投票/采纳/审核需幂等：相同操作返回相同结果 |
| **事务边界** | 外部调用（UOP / FCM / 翻译）必须放事务外，避免长事务 |
| **N+1 查询** | 禁止；列表查询用 `JOIN` 或批量 `IN` |

## 反例

```java
// ❌ Controller 写业务
@PostMapping
public Result<Long> create(@RequestBody Question q) {
    if (q.getTitle().length() < 5) throw new RuntimeException("标题太短");
    questionMapper.insert(q);
    return Result.ok(q.getId());
}

// ❌ 自定义错误码
throw new RuntimeException("999999: xxx");

// ✅
@PostMapping
@SaCheckPermission("question:create:any")
public Result<Long> create(@PathVariable Long groupId, @RequestBody @Valid QuestionCreateDTO dto) {
    return Result.ok(questionService.create(groupId, dto));
}
// ...
// Service 内
Assert.isTrue(dto.getTitle().length() >= 5, () -> new BusinessException(ErrorCode.QUESTION_TITLE_TOO_SHORT));
```
