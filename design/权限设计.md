# Engineer Online — 权限码注册表（Permission Code Registry）

> **用途**：本文档是 Permission Code 的**单一真相源（SSOT）**。所有后端鉴权、前端可见性控制、审计日志必须引用本表定义的码值，不得自行新增或修改。
>
> **关联文档**：
> - 角色定义：`requirement/00-需求总览.md` §1.5
> - 鉴权技术实现：`standard/技术架构.md` §10
> - 模块业务规则：`requirement/modules/05.x-xxx.md` §5.x.4

---

## 1. 命名规范

格式：`{资源}:{动作}:{范围}`

| 段 | 取值规范 | 示例 |
|---|---|---|
| **资源（resource）** | 英文小写单词，对应核心实体名 | `question` / `answer` / `group` / `vote` / `notification` / `translate` |
| **动作（action）** | 英文小写动词 | `view` / `create` / `update` / `delete` / `audit` / `accept` / `cast` / `resync` |
| **范围（scope）** | `any`（任意对象）/ `own`（仅自己创建的） | `any` / `own` |

**范围语义**：
- `:any`：不需要关心资源归属，直接放行
- `:own`：Service 层必须比对资源 `author_id / user_id` 与当前 `currentUserId()`，不一致则抛 `FORBIDDEN`

## 2. 角色简称

| 简称 | 英文常量 | 角色 | 端 |
|---|---|---|---|
| 管理员 | `ADMIN` | 运营管理员（`requirement/00-需求总览.md` §1.5） | 仅管理后台 |
| 官方号 | `OFFICIAL` | `OFFICIAL_ENGINEER` + `OFFICIAL_PM`（两类子类型权限等价，RR-04） | App + 管理后台 |
| 车主 | `OWNER` | 已认证车主 | App |
| 授权车主 | `AUTH_OWNER` | 被车主授权的使用者 | App |
| 全部 | `ALL` | 含游客 | App |
| 已登录 | `AUTH` | 任何已登录用户 | App |
| 作者 | `AUTHOR`（运行时） | 资源创建者（`author_id = currentUserId`） | App |

**说明**：
- `ADMIN` 不是 App 端角色，仅在运营管理后台生效
- `AUTHOR` 不是数据库中的固定角色字段，而是 Service 层在校验 `:own` 权限时动态判定的上下文角色
- 同一用户可以同时是"车主"和某条问题的"作者"

## 5. 实现约定

### 5.1 后端

```java
// Controller 注解校验
@SaCheckPermission("question:create:any")
@PostMapping("/api/v1/questions")
public Result<Long> create(@RequestBody @Valid QuestionCreateDTO dto) { ... }

// `:own` 范围必须在 Service 层补充归属校验
public void deleteOwn(Long questionId) {
    Question q = questionMapper.selectById(questionId);
    if (!q.getAuthorId().equals(currentUserId())) {
        throw new BusinessException(ErrorCode.FORBIDDEN);
    }
    // ...
}
```

**圈子级叠加校验**：当 Permission Code 通过后，Service 层需再读取 `Group.post_roles / reply_roles / follow_up_roles / access_roles` 判断当前角色是否被圈子允许。

### 5.2 前端

```vue
<!-- Vue 3 (管理后台/H5) -->
<button v-permission="['question:audit:any']">审核</button>

<!-- Flutter -->
Visibility(
  visible: AuthStore.hasPermission('answer:accept:own') && question.authorId == currentUserId,
  child: AcceptButton(),
)
```

### 5.3 代码常量生成

后端/前端统一通过 `TOOL-04` 任务（见 `tasks/任务清单.md`）从本表生成：
- Java：`PermissionCode.QUESTION_CREATE_ANY`
- Dart：`PermissionCode.questionCreateAny`
- TypeScript：`PermissionCode.QUESTION_CREATE_ANY`

编译时校验 code 是否存在于本表，避免拼写错误。

## 6. 变更流程

新增或修改 Permission Code 必须：

1. 在本表对应分组追加一行，填齐"默认角色/关联 BR/备注"
2. 同步更新 `requirement/00-需求总览.md` §1.5 权限矩阵
3. 同步更新对应模块 PRD 的 §5.x.4 业务规则（若引入新业务规则）
4. 更新 `CHANGELOG.md`
5. 重新运行 `TOOL-04` 生成代码常量

**禁止**：直接在代码里写裸字符串 `"question:create:any"`，必须通过生成的常量引用。
